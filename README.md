# Momo Store

## Конфигурация и Секреты
В проекте предусмотрена поддержка Docker Secrets для передачи чувствительных данных.
> **Внимание:** Блок `secrets` в `.gitignore` в данный момент **закомментирован**. Это сделано специально, чтобы автоматизированные процессы сборки и ревью (CI/CD) не завершались ошибкой в отсутствие локального файла секрета.
Проект использует файл `.env` для управления параметрами сборки и жизненного цикла контейнеров. Файл содержит следующие переменные:

| Переменная | Описание |
| :--- | :--- |
| `COMPOSE_PROFILES` | Профиль docker-compose |
| `DOCKER_REGISTRY` | Имя пользователя или адрес реестра (для `docker push/pull`). |
| `TAG` | Версия собираемого образа. |
| `BACKEND_REPLICAS` / `FRONTEND_REPLICAS` | Количество экземпляров реплик каждого сервиса. |
| `BE_CPU` / `BE_MEM` | Лимиты CPU и RAM для контейнера бэкенда. |
| `FE_CPU` / `FE_MEM` | Лимиты CPU и RAM для контейнера фронтенда. |

### Почему .env находится в репозитории?
Обычно файлы `.env`, содержащие секретные данные (пароли, API-ключи), следует добавлять в `.gitignore`. Однако в данном проекте этот файл **не добавлен в исключения специально**, так как:
1. **Отсутствие чувствительных данных:** Текущий `.env` содержит только инфраструктурные параметры (имена тегов, лимиты ресурсов).
2. **Заготовка под secrets:** При необходимости проброса секретов в контейнеры лучше воспользоваться блоком secrets.


## Режимы эксплуатации

Приложение поддерживает работу в двух профилях: `prod` (Production) и `dev` (Development). Активировать нужный профиль можно двумя способами:

### Способ 1: Использование переменной окружения (через .env)
Укажите в `.env` нужный профиль:

```bash
# Для продакшена:
COMPOSE_PROFILES=prod

# ИЛИ для разработки:
COMPOSE_PROFILES=dev
```

После этого запуск осуществляется обычной командой:
```bash
docker-compose up -d
```

### Способ 2: Явное указание профиля (флаг)
Можно передать переменную непосредственно в команду:

**Режим Prod:**
```bash
COMPOSE_PROFILES=prod docker-compose up -d
```
*В этом режиме применяются все политики безопасности и лимиты ресурсов.*

**Режим Dev:**
```bash
COMPOSE_PROFILES=dev docker-compose up -d --build
```
*Исходный код фронтенда и бэкенда монтируется в контейнер.*
